# v1.1.1

### Footage inside a composition paints in the export

The export now mounts every composition's template the way the service's own build does, so a `<video>` inside a composition is read on the host's clock and paints. The `aip-composition` skill no longer claims such a clip is not painted, and no longer names the `video_inside_composition` warning the service stopped emitting. A nested footage clip is documented beside the root clip with its whole tag, timed on the host's clock like a PIP; the root clip is what the user moves on the timeline, the nested one moves with its moment. The timing table names the nested clip beside the PIP as the `data-start` exception.

### Paths inside a composition resolve from the render-engine root

The editor mounts a composition's template content into `index.html` without rewriting URLs, so a `../public/...` path written from a composition resolves above the served root and the layer is empty in the editor.

- `workspace.md`: a media, image, stylesheet, `data-composition-src` or `data-pip-src` reference, and a CSS `url(...)` inside an HTML document, is written from the render-engine root whichever directory holds the document. Only a `<script src>` inside a composition is written from the composition's own file, because the export loads the composition as its own page.
- `preflight.py`: applies the same split, and reports `reference_outside_workspace` for a climbing `../public/...` or `../styles/...` path from a composition.
- The `nested_video_requires_player_validation` advisory is unchanged.

Requires the production service to apply the same root rule in `commit_workspace`.
