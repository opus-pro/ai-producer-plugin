# Edit in a reference video's style

A reference sets three things in the user's edit: the captions, the motion graphics (titles, text overlays, stickers, cards, animated graphics, and camera treatments such as punch-ins, shakes and flashes), and the transitions between beats. Everything else follows the [AI Producer skill](../aip/SKILL.md). Its [aesthetic rules](../aip/references/aesthetic-rules.md) hold here as over every fine cut: the reference decides how things look, move and cut, and the rules decide what the edit shows, how much of it and whether it reads. With a reference, its measured style outranks the rules' floors that only add variety (the punch-in minimum, a framing change at every jump cut, nothing arriving after its word, [layout variety](../aip/references/aesthetic-rules.md#35-layout-variety)); readability, the safe area, the contracts and the showcase floor (showcase shots never below 50% of the runtime) still come first. You copy the reference's style, never its content or its schedule: the reference decides how each graphic looks, moves and cuts, and what the user says at each beat decides what that graphic shows and how it is laid out.

## Get the reference

What getting, reading and matching a reference need on this computer, from downloads to the tools that read it, is in [tools.md](references/tools.md): read it before you get the reference.

- A video file the user gave you is the reference as it is. Images the user gave you are a reference of stills: copy them into one new directory in the project's working folder, in the order given.
- A link to a post on Instagram, TikTok or YouTube: get it as soon as you have it, while the user's footage is still being prepared, with `start_link_download` and the link, download what it answers, and from then on it is a video file the user gave you. Never download the post any other way, such as with a downloader you find installed.
- A preset: read it with `get_reference_preset` and its `preset_id`. A preset the user names or describes is matched by its name and look in `list_reference_presets`, which is also what you show, by name and look, a user who asks which presets there are. Its unpacked `folder` is what [reference_frames.py](scripts/reference_frames.py) writes for the preset's video, with its `caption-kit/` already made when the preset shows captions and its style pack when it was built with one, so you do not run the script for it, and a preset has no video to download or open. When the call answers that no presets are published, or that the preset is unknown or withdrawn, tell the user in one sentence and ask for a reference video, a link or images instead.
- A directory that holds `reference-index.json` is a reference already read, such as a preset's unpacked folder or the folder of one an earlier edit read: use it as it is, without running the script on it.
- A request sent from the AI Producer web page carries its reference in `get_web_assignment`'s answer: a `preset` with its `preset_id` and `catalogue_version`, both passed to `get_reference_preset`; a `link`, fetched as above; or a `video` or `images`, each file with a `download_url`, reading the assignment again for fresh links, used as a video file or a reference of stills. Start on the reference as soon as the assignment says it is ready, without waiting for the footage.
- When `start_link_download` cannot get the post, tell the user in one sentence what its refusal's `error` says and what to send instead. `link_unsupported`: only Instagram, TikTok and YouTube links work, so ask for one of those or the file; `link_download_busy`: say when they can try again from `retry_after_seconds`, and that the file works now. `link_download_unavailable` is a passing problem on AI Producer's side, not the post's: call it once more with the same link, and only when that answers the same ask for the file. Where the `error` names nothing to send, ask for the video file.

Start the user's own footage first, as the AI Producer skill says, so it uploads and prepares while you get and read the reference. Open the project's progress page as soon as `project_id` returns, before the reference is read, as that skill's progress section for this host says: the reading takes a while, and the user watches the project from the start.

## Read the reference

When the reference's folder holds `style/style.md`, it is already read into a [style pack](references/style-pack.md): read `style.md` and the visuals and templates it names first, and make no caption kit for it. A whole pack (its first line `Pack: whole`) is the entire reading: read `style.md`, and when it has an `## Evidence` section read the `visuals/` evidence files it names (entrance and exit span sheets, stills, grounds) for every beat the edit copies; otherwise open nothing else of the folder unless `style.md` leaves a question open, which one contact sheet, strip or keyframe then answers. An edit's pack (`Pack: edit`) holds every caption treatment but only the graphics one earlier edit used, so read its contact sheets and transition pages as well, as [reading a reference](references/read-reference.md) says, for the graphics and transitions it does not hold. A whole pack whose `style.md` has a `## Hook` section carries the reference's hook matched already, which the edit follows as [A preset's hook](#a-presets-hook) says.

When the folder holds no style pack, read the reference, pick its caption kit and keep its pack as [reading a reference](references/read-reference.md) says.

## What to copy

- **Captions.** The reference's caption look, matched against the caption kit and written as caption moments as [Matching the captions](#matching-the-captions) says, with the [dynamic caption skill](../aip-dynamic-caption/SKILL.md)'s timing and mounting. A reference with no captions of its own still gets captions, in that skill's plain look, which you write yourself once the cut is final, with no kit and no subagent.
- **Motion graphics.** The look of the reference's graphics: their typography, palette, shapes, line, texture and motion verbs, how their parts enter, stress and leave. The layout of each graphic (an overlay, a seat, full cover, a split, a cutout, a sticker or an object) is chosen from what the user's line at that beat is about: a layout the reference never shows is in style when it is built from the reference's look, and the reference's own layout is used where the user's line needs it. Recreate each graphic as a composition under the [composition contract](../aip-composition/SKILL.md), filled with the user's own content: their words, their facts, their imagery, which is what they supplied and never a still of their footage, as the aesthetic rules' [material section](../aip/references/aesthetic-rules.md#1-material-real-things-as-real-imagery-concepts-as-animation) says. A graphic copies the reference's look, its type, palette, line, texture and motion, and never what it depicts: draw the thing the user's line is about, in that look, arranged as that thing needs, and make objects behave as real ones do. A hand, a body or a figure the reference drew holding, pointing at or reaching for its subject is part of what it depicts: draw the user's subject alone, carrying the motion the hand did, and draw a hand only when the user's line is about holding, giving or reaching, posed the way a hand holds that thing. A shape the reference drew for its own subject, such as an abstract wave or a dot sphere, is used only where the user's words have something it shows. A kind the style pack holds is a sample of that look, used as the [style pack](references/style-pack.md) says. Read [graphics rules](references/graphics-rules.md#motion-graphics) before authoring any graphic (motion fidelity, named products, lists, containers, 2D vs 3D).
- **Transitions.** How beats hand to each other: a hard cut, a punch-in, a flash, a whip or slide, a blur, a mask, and how text and graphics leave as the next beat arrives. Read each boundary's `kind` against its row, and look for what it cannot name, such as a slide, a mask or a punch-in. Use the transitions the reference uses, about as often as it does. A transition the reference does not show is not used: no flash, shake, whip or glitch it lacks, whatever the creative direction would otherwise add, and a reference that only cuts hard gets hard cuts. Each transition goes only on the joins the reference makes, at its point in the sentence, the captions running through it as the reference's do; a full cover holds through its phrase, with no sliver of the speaker between two covers.
- **Cutting rhythm.** How often the picture changes: `cuts_per_minute.whole` is the reference's rate. When the reference cuts between shots and the user's footage is one continuous shot, carry that rhythm with reframes of the speaker: at a sentence or phrase boundary, change hard to another framing - full frame, a tighter one on the face at the scale the reference's own punch-ins use (1.3x where it shows none), a recomposition toward one side - as a zoom effect host with no ramp in or out, held for the stretch it frames. Count the visual moments' own changes toward the rate, and alternate framings so no two in a row match. A reframe never removes speech: what is said is the rough cut's alone.
- **Proportion.** Keep the reference's balance between the speaker on screen and showcase shots, within the floors the aesthetic rules' rhythm section sets. What fills a showcase shot is chosen from what the user says at that moment, never to use every treatment the reference has: a treatment goes where the user's content fits it, at most about as often and as long as the reference uses it, and where none fits, a graphic of the user's own subject in the reference's look fills the shot.
  - Footage or photos as shots of their own (B-roll; logos and product screens follow the product rule above) appear only where the reference shows them, at about its share, clip length and place in the sentence, in its container and treatment (black and white, tint, duotone), a clip where the thing moves, its treatment read on each insert's first and settled frames (a clearing from soft or blocky to sharp included); where the reference shows none, research none. The treatment is for inserted footage only, never the speaker's own shots.
  - When the reference never shows a speaker and the user's footage does, the speaker carries the edit, dressed in the reference's devices (full frame under its captions and overlays, inside its frames or cards, cut out on its grounds). Its most striking element is not a reason to run it across the whole edit, and one it shows once stays a one-off. The times, frequencies and runtime shares a style pack's `style.md` gives are facts about the reference, never a schedule: a kind's frequency is at most a ceiling for the reference's signature kinds, so a reference that runs one graphic back to back does not make the edit do so; a signature treatment of the reference's body recurs through the edit's body at about its rate, a floor as well as a ceiling, never spent in the opening alone. The speaker stays on screen where the reference keeps its speaker on screen, within the 50% showcase floor.

A reference of stills shows the captions, the motion graphics, the palette and the layout, but no transitions, cutting rhythm, motion or timing. Copy what the stills show, in about the balance between speaker and graphics they show, and the AI Producer skill's creative direction decides the rest.

Leave the reference's content out:

- its subject and motifs, brands, logos, people, product screens, screenshots, signature indicators and words, as words, drawn shapes or arrangements;
- anything that belongs to the platform or the recording rather than the edit: play buttons, progress bars, usernames, watermarks, the platform's own captions and stickers, a cursor or a recording frame.

This covers the reference's content only: a product, app, organisation or person the user names is the user's content, shown as above with its own logo and colours.

When a treatment carries a kind of material the user's footage lacks, such as a screen recording or a product shot, find the user's own equivalent through the AI Producer skill's visual research or author it (a named product only as a real capture or faithful interface recreation), or give that treatment a different payload from the user's content.

The user's frame decides geometry. When the user's footage differs from the reference in orientation, framing or length, keep each treatment's character and place it with the [framing skill](../aip-framing/SKILL.md). A graphic above the head clears the hair, not only the face box, at the largest zoom over it; with less room it takes another layout, never the face.

Where the reference and the AI Producer skill's creative direction disagree about the look of the captions and motion graphics or the kinds of transition, the reference wins: no flash, shake or whip it lacks. It does not win on the layout of a beat or on how often a kind appears, which the user's content and the aesthetic rules decide. Everything the reference does not show, the direction still decides. The user's own words outrank both, and the aesthetic rules outrank the reference in the order they give, except for the variety-only floors above. That includes a style pack's own text: a slot it says to fill with a frame of the user's footage, or a beat it builds from the user's recording at another moment, is filled as the [material section](../aip/references/aesthetic-rules.md#1-material-real-things-as-real-imagery-concepts-as-animation) says.

## A preset's hook

When a whole pack's `style.md` has a `## Hook` section, read [the preset's hook](references/preset-hook.md) before you plan the user's opening: its hook was matched once, when the preset was built, so an edit copies it rather than matching it again. A reference without that section has its opening copied like the rest of it, as [What to copy](#what-to-copy) says.

## Plan the beats

Once the cut is final, before the table below, list every product, app, organisation and person the user names, and research each as the AI Producer skill's [Source supporting visuals](../aip/SKILL.md#source-supporting-visuals) says, on a preset edit as on any other: a web search to confirm what the name is, then its official logo, screens or footage from official sources first (press kits, media rooms, the product's own site), then Wikimedia Commons and Openverse (preferring CC0 / public domain, never rendering license notices on screen). Search each name as it is heard: a search may correct only the spelling of that same-sounding name (GrokBot for Grok Bot), never swap in a different name because it fits the context better, and the captions and every graphic keep the word the user said. Only a name no search confirms, or one with no usable official mark, takes a neutral drawn icon, and the reply that hands the project back names that beat.

Once the cut is final and before you author any graphic, write one short table in a file in the project's [working folder](../aip/SKILL.md#working-folder), one row per graphic beat, a preset hook's rows first: the beat, the user's words it carries with their times, what those words are concretely about (the thing, number, action or contrast a viewer should see), the layout family that shows it best, and what it borrows from the reference (faces, palette, texture, an entrance or exit, a template). Check the table as text against the reference's own balance and the showcase floor: count each family's beats, the longest stretch in one family and the showcase share, and keep them near the reference's, the showcase share never below the aesthetic rules' 50% floor.

- Each row first says what the sentence means: an idiom or metaphor is read as its meaning (doing the hard work, not a weight), and the graphic shows what the whole line means, never one word's noun.
- The opening copies the reference's opening from its first frame, mapped onto the user's first claim, and ends on the claim's last word, never running into the next sentence.
- Check every row, the pack's kinds, palette and templates, and later each clip or image the edit picks, against Leave out, renamed or not. The reference's brand colours (on a logo, app icon or product mark, or a rim, glow or gradient echoing it) and subject-specific illustrations (a product's shapes, a chart line drawn for its words) are content too: take colours from the reference's other graphics and the user's own brand instead.
- The user's words fill the reference's line roles in order (lead, main, accent), each role keeping its look; an accent crosses its line only as far as the reference's does so every line stays readable. Each opening stack row takes as many of the user's words as its range allows, in spoken order, the accent on the stressed word; a stack tied to one shot ends on the user's picture change, the rest carrying on as the next stack. It is a plan of a few lines per beat, checked without renders; the graphics follow it.

## Full covers and pre-commit checks

Before authoring any full cover or committing a page, read [graphics rules](references/graphics-rules.md#full-covers): full covers use display labels rather than caption sentences when captions stop, fill about half the frame, cover all four corners on reveals, and every graphic and page passes its [pre-commit checks](references/graphics-rules.md#before-each-commit) before commit.

## Working files

Keep the files you make while reading the reference and matching the captions in directories you create for them in the project's [working folder](../aip/SKILL.md#working-folder), the rows and report files included, and name them by their full paths. Redo or delete them as [tools.md](references/tools.md) says.

## Matching the captions

This section is for a reference that shows captions. Its captions are written as soon as the cut is final, which it is once the rough cut is written in your local `render-engine/` directory: graphics, framing and sound never move the words, and nothing needs publishing first. Run `caption_cues.py` on that directory then, as the dynamic caption skill says, and keep the rows it prints in a file.

When a whole pack's `style.md` says its caption treatments are matched for an edit's shapes (one, two and three words, a long word, each line role), write every caption moment yourself from those templates with the user's own words and times, as the [style pack](references/style-pack.md) says, with no subagent and no kit; then render each treatment once over a frame of the user's footage beside its kit frame and evidence still, and change what differs. Only a treatment that render shows wrong, or a pack whose captions are not matched for those shapes, goes to the caption match in a subagent where [tools.md](references/tools.md) gives it one, using the pack's templates as its starting point. When a style pack holds its caption treatments and no evidence, they are matched already: write every caption moment yourself from the templates, as the [style pack](references/style-pack.md) says, with no subagent and no kit; stage the faces `style.md` names; then `compare` a page that mounts one of them over a frame of the user's footage, beside that frame, to see that it reads there and that a part that lets the picture through or blends still does over that picture, and publish.

Copy the reference's contrast, not only its colours: place the block (centred horizontally where the reference centres it, moved up or down only) on the part of the user's frame closest to the reference's ground behind it (a dark shirt, a laptop, a shadowed wall); only where none is near, keep each colour's hue and shift its lightness and glow strength until the text and glow stand out as on the reference, checked over the frames each cue covers. Never add a shadow, plate or scrim the reference lacks, and never move a colour to another hue. A reference whose pack holds no captions is matched against its caption kit as [reading a reference](references/read-reference.md#matching-the-captions) says.

[caption_compare.py](scripts/caption_compare.py) does the plumbing, run as `uv run --with fonttools python <the script> <command>`: `fonts <name>` lists the installed faces of a family, `specimen <out.png> <frame> --text "<words>" --crop X,Y,W,H --size <px> <family>` sets the words in every face of the family under that part of the frame, `extract <font file> <index> <out.ttf>` splits one face out of a collection, and `compare <out.png> <frame>=<page> --crop X,Y,W,H` renders a page at the frame's size beside the frame, cropped to that part at full resolution. Replace a page, an image or a caption moment you rebuild as [Working files](#working-files) says.

Each part of the caption, a line, an emphasized word or a fill, is its own [moment](../aip-composition/SKILL.md) host over the frame, each host its own layer as in the edit, and a part that blends with the picture carries its blend on its host, as the composition contract says. What matches on the page then goes into the edit unchanged but for its words and times. A line already on screen keeps its exact place when the next line of its group arrives, as the reference's lines do.

The pages render locally with a headless browser, as [tools.md](references/tools.md) says. They are reference analysis before publication: they are never staged or uploaded, and they are not an inspection of the edit.

The captions' fonts are font files staged with them, since the export machine has none of this computer's fonts: a face installed here is staged from its own file, a collection such as `.ttc` split to the face the captions use, and only a face you cannot get as a file takes its closest open family. Whether a face's license allows staging it is reviewed outside the edit, so the captions never swap a face for an open family over its license. When downloading an open family, use only its official source (its foundry, repository, or Google Fonts), never a mirror's copy, keeping a script as a script; roles of one class fold into one face within the aesthetic rules' two families, and a third class the reference shows keeps its face. Weight, tracking, baseline, stacking, overlap, layer order, glow, shadow, edge light, and how stacked lines relate in width match the reference, with stacked-line widths written as a width-fit rule in code. Their colour is drawn in CSS, never with the reference's own pixels.

## Tell the user

In the message that says the run has started, say in one or two plain sentences what you are taking from the reference - the caption look, the kinds of graphics, the way beats change - and that the content will be their own. Name no file, tool, frame count or window. A reference you could not get or read is said once, in the same plain words, with what the user can send instead.
