# Acting on a Motion Library reference

A natural-language request followed by an AI Producer reference URL is both an instruction and a reference to the selected Motion Library card. Resolve it through the service, then adapt that card to the current video's content while preserving its recognizable design and motion. Use one relevant occurrence when the user gives no count. An explicit request to insert the card unchanged keeps its original content and takes the direct path.

A legacy line that starts with `@aip` remains a supported reference. Resolve it through the same boundary and preserve an explicit legacy "here" time unless the user's current words override it. The catalogue behind every reference lives on the service; never parse a URL or legacy line yourself, duplicate the catalogue here, or guess another card when resolution fails.

Read this once for a Motion Library handoff. The [AI Producer skill](../SKILL.md) owns user-facing language, existing-project scope, and the delivery boundary. The [framing skill](../../aip-framing/SKILL.md) and its [cutout reference](../../aip-framing/references/cutout.md) own speaker measurements, while the [composition contract](../../aip-composition/SKILL.md) owns a derived composition.

## Resolve, ground and place

1. **Resolve the whole request first.** Call `resolve_selection` before another AI Producer call, passing the complete pasted prose and reference as `selection`; include `project_id` when the request already targets the current project. A new URL resolves to top-level `schema_version: 2`, `project_id` and `references`. Its reference carries `project_id`, `kind: "motion_asset"`, a pinned `address` with `kind: "motion-asset"`, `id` and `version`, null `composition_id` and `region`, compatibility `at_ms`, `reference_id`, `expires_at`, `intent` (`adapt` or `direct`), `placement`, `context` and `availability`. `placement` is either `{"mode":"auto"}` or an explicit `at_ms` with an optional `duration_ms`. For automatic placement, the reference's compatibility `at_ms` is null even when `context.playhead_ms` records where the library was browsed; that playhead is context, not an instruction. The user's current words override copied intent and placement. A different target project requires explicit user intent and a fresh access check. Report invalid, expired, inaccessible, mismatched, retired, or unavailable references and stop; never substitute another asset or bypass the refusal through creative authoring.
2. **Read the current edit before choosing content or time.** Read the project, transcript, retained output timeline, existing visual moments and relevant accepted project media. Reuse valid context already present in the task. For automatic placement, scan broadly, then read the best candidate beat closely; inspect the original input around that beat only when a gesture, prop or visual event decides the fit. Compare semantic fit, useful information gain, readability, existing visuals, captions, speaker clearance and the template's purpose. Choose one suitable retained beat unless the user requested more. Do not place at zero or at `context.playhead_ms` merely because no target was stated.
3. **Honor explicit scope.** An explicit output time or range wins over copied and inferred placement. Map source cues through the current cut rather than treating source time as output time. If the timeline changed after the reference was created, re-resolve the intended beat and current revision; do not silently move or clamp an explicit target. Preserve unrelated graphics, audio, captions and edits.
4. **Ground every semantic value.** Replace demo topics, names, copy, figures and media with facts from the user's instructions, transcript and accepted project assets. Preserve qualifiers and units. Never invent a number, example, quotation or asset to fill a template. Infer missing inputs from known context before asking; ask one focused question only when the intended visual cannot be completed responsibly from the available evidence.
5. **List for the final window.** Once the output window is settled, call `list_motion_assets` with that exact `at_ms` and `duration_ms`. Find the entry whose `motion_asset_id` and `version` match the pinned address and retain the returned `project_revision`. Treat `add` as technical capability, not proof that demo defaults are editorially correct. Follow the selected entry's supported action and inputs; a refusal remains a refusal.
6. **Prefer the original package when its supported slots are sufficient.** For `intent: "adapt"`, bind declared `parameters` and `media_inputs` only when their manifest inputs carry a supported `binding` with `storage: "parameter"` and a token, and those slots can express the grounded visual. Key each submitted value by the manifest input's exact `key`, never by its binding token. Then call `materialize_motion_asset` with the final `timeline_in_ms` and `duration_ms`, the listed `expected_project_revision`, and a fresh `idempotency_key`. If the entry returns `chooseInput`, infer listed values from the current context first and use `present_choices` only for a value that remains unknowable. Preserve signature design tokens, animation and layout. For `intent: "direct"`, materialize the unchanged package defaults at the resolved final target.
7. **Derive only when package inputs cannot express the change.** When relevant content is hardcoded, an intended semantic slot is unbound or uses overlay storage, or the required structure or element count must change, call `get_motion_asset` for the pinned id and version, read only that source and manifest, and derive the smallest necessary change under the composition contract. Do not submit unsupported bindings and claim the defaults were adapted. Preserve the template's recognizable design and motion. Commit the result at the final window through the existing workspace flow. Never use derivation to work around retirement, authorization, compatibility or availability.
8. **Keep retries safe.** Reconcile a stale revision against the current edit before another write. Keep the same `idempotency_key` when retrying the same materialization and use a new key only for a distinct placement. Do not blindly replay a paid generation or overwrite another accepted edit.
9. **Verify from the receipt and hand back the durable page.** Confirm materialization from its receipt (`instance_id`, `timeline_in_ms`, `timeline_out_ms`) or a derived edit from the accepted workspace receipt. Return `page_url`, retrieving it from the current project when the receipt omits it. Briefly name the chosen beat and why it fits. Do not return `agent_page_url`, and do not play, screenshot or otherwise inspect the generated preview.

## Cutout packages

Choose the final output window before listing so the returned cutout plan is measured for the kept spans that will actually appear. The selected entry's `next_data.cutout.frame_speaker_calls` carries the measurement calls, with one window per kept span inside that effect window, split at cut boundaries, together with the package measurement inputs and revision. Run those calls as supplied. Do not widen, merge, shift or guess a window, and never bridge two takes with one matte.

Bind one segment per accepted window, in order. Use that window's staged `path` and `sha256`, cut `start_ms` and `end_ms`, `object_position.css`, and cutout values (`sink_px`, `card_clip_top_px`, `head_top_px`, `head_bottom_px`) exactly as returned. Leave out a window whose measurement reports `presence.matte_ok` false or a null cutout and name the omission to the user; when none survives, report that instead of placing.

Pass the `project_revision` from the listing that produced the windows. On a stale revision, list the same final window again, compare kept spans, re-run `frame_speaker` only for spans that moved, and reuse unchanged accepted files and geometry.

## Legacy Scene restyle references

An `omni-preset` stays on the legacy `@aip` reference shape and Scene restyle path. The selected preset remains the style identity. Read `scene_restyle` from the listing and match its slug. Ground only the allowed supplement in the relevant beat; do not replace the preset with a loosely similar authored effect or restart an unrelated whole-video edit.

When Scene restyle is disabled, ask once whether to enable it for this project and pass the user's literal answer as `enable_skill_quote`. State the current price from the tool description and obtain the user's go-ahead before the paid call; combine these into one decision when both are needed. Respect an explicit window, otherwise choose one content-based 4 to 10 second window. Call `generate_scene_restyles` with the selected preset and window, keeping `prompt` empty unless the user requested a supplement. Do not infer authorization from copying the card or replay a paid call after an uncertain outcome.

Use the finished task's verdict as the receipt. When the service scaffolded the tree, it mounts the cover; add nothing. On an authored tree, mount the reported cover once as the index-level `<video id="omni-<cid>" class="clip">` on its own track, with the reported path, window, `muted`, and `data-volume="0"`, then commit the index through the workspace flow.

## Talk to the user

Follow the AI Producer skill's language contract. Name the template as the user sees it and the chosen time or beat, while keeping reference ids, package ids, versions, revisions, keys, hashes and paths inside calls. Ask only for an unknowable required input or the Scene restyle authorization above. Everything else is a concise report of what was applied, or why it could not be and what the user can do next.
