# A new project's reference question and finishes

This extends the [settings for a new project](../SKILL.md#settings-for-a-new-project). Read it once at the start of every new project, before the message that says the run has started, and before a change to an existing project that touches its captions, sound effects or music or moves its cut.

## Ask for a reference

A new project whose opening request gives no reference gets one question about a reference, the only question a new project asks: the user may not know that AI Producer can copy a video's style, and this is where they learn it. A request gives a reference when it carries a video or images the user offers as one, a link to a post, or a preset named or picked. Do not ask on a request sent from the AI Producer web page, whose web assignment already holds the user's choice with or without a reference; on a change to an existing project; when the user said they want no reference or no particular style; or in ChatGPT.

Ask in the message that says the run has started, and end the turn with it, in the user's language, as a plain numbered list, never a card or a question tool, because the answers are pasted text and attached files:

1. Pick a style preset in the panel beside this chat and paste what its Recreate button copies.
2. Paste a link to an Instagram, YouTube or TikTok post.
3. Send a reference video or images.
4. Skip, and AI Producer edits in its own style.

That message still names the settings and carries the price of preparation, as the [settings for a new project](../SKILL.md#settings-for-a-new-project) say.

Right before you send it, once `start_transcribe_project` has returned, call `get_view_url` without `project_id` and `list_reference_presets`. Offer the first option only when the first answers with a link and the second lists at least one preset; a refusal (`presets_view_not_available` means the account is not offered the presets yet), an error, or an empty list leaves it out and renumbers the rest. With both, show the presets as [the presets page](host.md#the-presets-page) says for this host, as the turn's last calls before the question: the presets appear together with the options that explain them, never during the upload, when nothing in the conversation says what they are for. The user answers with a preset's id or name, or pastes what its Recreate button copies.

Send the question as the last message of the turn, with the project link, and end the turn. Nothing else runs before the answer, the rough cut included: a question asked while the work goes on is easily missed, and the user then meets an edit their pick should have shaped. While the question is open the presets stay beside the conversation; open the project's progress page only after the answer, before any other work.

Read the answer. A pasted Recreate prompt names a preset by its id and catalogue version: read it with `get_reference_preset`, passing both, and when that version is no longer offered, read the id alone. A preset the user names is matched in `list_reference_presets`. A link, a video or images are the reference. Only an explicit skip or decline means no reference, and the fine cut then follows the creative direction. A reply about something else, such as a question about the price, a change to a setting or a problem with the upload, is answered as usual and keeps the choice open: never repeat the question, and end that turn too, with one line saying the pick is still open. Once the reference is settled, write the rough cut and then everything the reference shapes: reading a reference, captions, motion graphics, transitions and the reframes that carry its cutting rhythm.

## Captions, sound effects and music

**Captions.** You write them as caption moments, as the [dynamic caption skill](../../aip-dynamic-caption/SKILL.md) says, in its plain look unless a reference or the user's words describe another; a saved default that names a caption pattern means captions on, in that plain look. Footage that already shows its own captions of the speech gets none of yours while they show, as that skill says. Never call `build_captions`. `no-caption` is the saved default's word for captions off: write no caption moments. For an existing captioned project the user wants without captions, remove only its caption hosts - caption moments, or a `narrator-captions` host the service built - preserve transcript and editor artifacts, then commit the changed root with `commit_workspace`.

**Background music.** Off unless the user or the saved default turns it on; on is the instruction to call `add_music` afterwards. Off declines a new music run; it does not strip a bed already mixed into the cut, so do not offer to take music away with it.

**Sound effects.** On unless the user or the saved default turns them off: place sound effects from the library on this project. Read the whole library with `list_sound_effects`, a page at a time (`limit: 50`, then each `next_cursor`), and choose every sound from what it lists. Never call `add_sound_effects`; when no listed sound fits a moment, leave that moment without one. Work as a short-form editor does: mark the moments, decide how many keep a sound, then match one sound to each, every time in integer milliseconds on the finished cut's timeline, never the source's.

Mark the moments from the transcript, the cut's timeline and the compositions you wrote:
- Mood: the feeling the clip is edited for. `funny` when it plays for laughs (a skit, jokes, banter, a prank, a comic dub, a meme edit); `tense` when it builds suspense or danger the viewer is meant to feel (a chase, a close call, a high-stakes play, a countdown); `serious` for news, health, grief, conflict or another sensitive matter told straight; `neutral` for anything else. A serious, informational or promotional clip with a light joke in it is not funny.
- Beats: mark every real beat that could take a sound: the hook, setups and payoffs, jokes, list items, edits, graphics or emoji popping in, visible motion. Judge meaning, not keywords; a clip with no real beats gets none. Mark the opening only when a title, graphic, pop-in, cut, visible motion or a punchy opening line earns it; on a plain open, let the voice start clean. A list said item by item is one moment per item; items that appear together are one moment.
- Anchor: put each moment where its sound lands, where the viewer first sees it, else where it is heard: on the edit for a cut or a reframe; on the frame where a motion lands (its contact or impact, an element's first frame, an animation inside a longer composition included); on a word for something only heard. A hit after a line with nothing on screen to land on goes at the end of its last word, never over the words. A word and what illustrates it are one beat.
- Priority: high for the hook, a payoff or punchline, a reveal, a graphic that is the point, a title card naming the topic, or a call to action; medium for a clear beat (a list item, an emphatic line, an emphasized keyword or key number landing on screen, a pop-in, a visual change that lands), every item of one list alike; low for a real but optional beat. Any element popping in on screen is a pop-in; a caption appearing is not a motion to mark, but an emoji or sticker in it is.
- Visual end: for a visual with a clear end its sound should stop with (text typing out, data or loading running, a graphic, emoji or sticker that comes and goes), give the hit `lasts_ms`, how long it stays after `at_ms`: the sound fades out 400 ms after it ends.

Keep a sound for the most important moments, higher priority first, then the earlier:
- Budget: unless the clip is funny or the user sets the count, at most one sound per 3 s of cut on average (at least one), a ceiling, not a quota. Pop-ins and list items do not count toward it and are never dropped for it. A serious clip keeps no low moments.
- Spacing: nothing in the cut's last 250 ms. Moments closer than 500 ms, or 250 ms for two items of a list said one by one, are one beat that keeps one sound; a build landing on its payoff counts as one beat.
- Tension: at most one Tension & Build sound (a riser, a ticking clock, countdown beeps) in any 60 s, on the hook or the biggest build; the other moment takes a hit or nothing.

Match each kept moment to one sound:
- Palette: funny takes comedy and meme sounds; any other clip that is not serious takes only a light one, for a clear joke the speaker makes. Tense takes tension sounds to build and a hit to land the release. Serious takes restrained low hits, never meme, cartoon or crowd sounds. Neutral lets what the moments show set the sound: cinematic hits, glitch and UI sounds for tech and science; clean, bright pops or clicks for a product, app or how-to, with a solid hit on the call to action; a light touch for someone talking about their day.
- Weight and tone: `intensity` follows priority, big for high, medium for medium, subtle for low. Deep or Sub for heavy, serious or cinematic moves; Warm, Bright or Airy for light and upbeat content.
- Payoffs and jokes: a payoff or reveal the speaker builds to takes a build into it (a short riser over the words leading up to it) or a hit on it, never a pop or click. On a punchline, reveal, realization, fail or reaction, prefer a meme sound that fits over a cartoon one; cartoon sounds are for slapstick, a physical gag, a face reacting, or something popping in or vanishing. A list that plays for laughs takes the same meme hit on every item, back to back.
- By kind: a click for something pressed or selected, a pop for something appearing, a multi pop when several appear together. A hard cut to a new place (another location, or between inside and outside) takes a camera shutter, never a whoosh, and two cuts in a row never take the same shutter; a jump cut or reframe in the same scene takes a sound only when it lands a payoff. A whoosh only when the camera moves (a zoom, a whip pan) and a swoosh when something on screen moves, matched to its speed; never on a hard cut, a still title or a spoken line. A transition's look names its sound: a white flash a camera flash, a light leak a shutter, a paper tear a paper rip, a scribble a chalk or pencil scratch, a glitch or shake a glitch sound. A screen recording matches its interface (clicks, typing, a notification or payment popping up), and notification sounds go only with a message, a phone or an app in the story. Punches only for physical action. A real action on screen takes its real sound.
- Room and quiet: a sound plays on past its moment for its length minus where it lands; prefer one that ends before the next kept moment. A loud or long sound that runs past the quiet until the next spoken word plays over the speaker: a boom or sub impact needs 1 s of quiet, else take a lighter accent or nothing, and a voice line goes only in a gap in the speech.
- Variety and lists: do not repeat a distinctive sound (a meme, voice line, boom, sting, crowd reaction) within about 20 s. Everyday sounds (pops, clicks, shutters, whooshes, typing) may repeat, but not on two moments in a row, except a list's items: its first three items share one sound, and from the fourth it switches to another of the same kind. Cartoon sounds never go on a list item.
- Follow each sound's `use_when`: it says when the sound fits, how much room or quiet it needs, and which sound is the first choice for its kind of moment.

Each hit names a `sound_id` and its `at_ms`. Leave `anchor` out, so the sound's `default_anchor` lines up: its peak lands on the moment, or, for a sound that starts with its action (a reaction, typing), its start. Name `first_hit` only to land the first of several `hits_ms` on the moment; a sound whose `hits_ms` fall on a run of actions' beats carries the run as one effect.

Place them once the cut and its timed treatments are settled, in one `place_sound_effects` call that carries every hit and `replace: true`, so a project that already has effects is not given a second set. When a later edit moves the cut, list again and place the whole set again the same way. Leave `replace` out only to add a sound to the ones already there, as when a call placed some hits and refused others: send each refused one again, corrected, with a new `idempotency_key` and the `project_revision` that call returned. A call that placed none (`nothing_placed`) changed nothing, so send the corrected set again with `replace: true`.
